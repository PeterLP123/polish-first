# Polish content and audio QA

Polish First must distinguish three different claims:

1. **Device Polish voice** — speech generated by the browser or operating system. This is the current fallback and is labelled as such in the interface.
2. **Human-reviewed text and phonetics** — the Polish, English intent, and learner-facing sound guide have been checked aloud by a fluent/native Polish reviewer.
3. **Native recording** — a consented human recording has passed the same text review and has documented usage rights.

No item may be marked reviewed merely because it passes automated schema checks. The manifests are intentionally empty until a human review takes place.

## Priority queue and coverage

Run:

```sh
npm run audit:content
npm run audit:content -- --json
```

The audit covers the first 200 phrases in course order, validates every claimed review and audio file, prints current coverage, and lists the next queue. `--strict` is available for a future release gate once the human work is funded; today it is expected to fail while reviews remain pending.

## Text and phonetic review

For each phrase, a Polish reviewer should:

- confirm that the Polish is idiomatic for the stated situation and register;
- confirm that the English expresses the intended meaning rather than a misleading word-for-word gloss;
- say the phrase naturally, compare it with the sound guide, and correct misleading stress or consonant/vowel cues;
- record their reviewer identifier, ISO review date, and a short note in `src/data/content-review-manifest.js`.

The reviewer identifier can be a project-controlled code; personal data is not required. A second reviewer should resolve disputed formal/informal usage or gendered forms.

## Recording workflow

1. Freeze the reviewed phrase text.
2. Record a native speaker in a quiet room at 44.1 or 48 kHz, with peaks below clipping. Keep the clean master outside the web bundle.
3. Export a compact web file to `public/audio/reviewed/<phrase-id>.mp3`.
4. Confirm pronunciation, pace, leading/trailing silence, and exact text against the reviewed phrase.
5. Add an entry to `src/data/audio-manifest.js` with the phrase ID, exact Polish, public path, reviewer code, ISO date, and usage-rights reference.
6. Run the audit and the browser tests. The app will then prefer that recording automatically; missing or invalid claims fail the audit.

Do not add AI-generated speech to the reviewed manifest. It may remain available only through the clearly labelled device-voice fallback.
